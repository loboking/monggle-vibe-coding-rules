# 하네스 방법론 적용 분석 보고서

## 1. 적용 가능성: ✅ 높음

### 현재 내재된 하네스 요소

| 요소 | 현재 구현 | 사용자 인지 필요성 |
|------|----------|-------------------|
| **Computational Guide** | PRD 템플릿, ShellCheck | ❌ 없음 (CI 자동) |
| **Inferential Guide** | Pipeline Gate, Verdict | ⚠️ 부분 (/pipeline 시) |
| **Computational Sensor** | TDD tests (Python + bats) | ❌ 없음 (CI 자동) |
| **Inferential Sensor** | /stats 통계 | ✅ 있음 (수동 실행) |
| **Progressive Disclosure** | commands/ 20개 스킬 | ✅ 있음 (스킬 호출) |

### 정채성(투명성) 평가

```
┌─────────────────────────────────────────────────────────────┐
│  설계 목표: "사용자가 몰라도 되는 하네스"                    │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  [사용자 관점]                                             │
│  /prd → /pipeline → 완료                                   │
│                                                             │
│  [실제 작동]                                               │
│  PRD 작성 → Gate(가이드) → Scan(센서) → Fold → Verdict    │
│           ↓ 자동               ↓ 자동        ↓ 판단        │
│  사용자는 "Verdict"만 확인                                  │
│                                                             │
│  ✅ 달성: 가이드/센서가 백그라운드에서 작동               │
│  ⚠️ 개선 필요: 루프 탐지, 개선 제안 자동화                │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 2. 설계상 문제점

### 문제 1: Doom Loop Detection 누락

**증상**: 같은 파일/작업을 반복 수정할 때 감지 불가

**영향**:
- AI가 동일 실수 반복
- 시간 낭비
- 사용자 frustration

**해결**: `.harness/loop-detection.json` + 자동 탐지 로직

### 문제 2: 개선 제안이 "보고"에 그침

**현재**: /stats는 통계만 표시

**필요**: 통계 → 패턴 분석 → 개선 제안 자동 생성

```python
# 예시: 개선 제안 자동화
if success_rate < 0.8:
    suggest("guide_addition", "Gate 템플릿에 예시 추가")

if fix_verdicts > 5:
    suggest("sensor_addition", "PRD Validation 규칙 강화")
```

### 문제 3: Progressive Disclosure가 문서화되지 않음

**현재**: commands/ 폴더가 존재하지만, "언제 어떤 스킬을 쓰는지" 안내가 없음

**해결**: CLAUDE.md에 스킬 가이드 추가

| **지속적 개선** | On-the-Loop으로 하네스 자체 개선 | ⚠️ 추가 필요 |

# fix

참고 파일 위치: 저장소 안이면 `skills/fix/references/`, 아니면 `~/.monggle/skills/fix/references/`.

## 1. 영향 범위 (항상)
`references/impact.md` 절차로 바꿀 대상의 호출처·공유 상태·계약을 찾고 위험도(高/中/低)를 매긴다.
`/fix --dry` 또는 "영향만 봐줘"면 여기서 보고하고 멈춘다.

## 2. 증상별 절차 (해당할 때만 읽는다)
| 증상 | 참고 파일 |
|---|---|
| 원인을 모름, 오류·크래시 | `references/debug.md` |
| 느림, 병목 | `references/bottleneck.md`, 측정이 필요하면 `references/profile.md` |
| 메모리 증가, OOM, 누수 | `references/mem-check.md` |
| 구조 정리·리팩토링 | `references/refactor.md`, `references/complexity.md` |

추측으로 고치지 않는다. 재현하거나 근거(로그·측정·코드 경로)를 먼저 잡는다.

## 3. 수정
- 1단계에서 찾은 엮인 코드를 먼저 읽고 고친다. 공유 함수의 근본 원인을 한 곳에서 고친다.
- 요청 범위 밖은 건드리지 않는다.

## 4. 회귀 점검 + 보고서 (생략 금지)
1. 바뀐 파일과 바뀐 심볼을 쓰는 곳을 다시 grep 해 깨지지 않는지 본다.
2. 메모를 쉬운 말로 쓴다(사람이 읽고 결정할 수 있게, 전문용어·로그 붙여넣기 금지):
   ```
   - 문제: <무엇이 왜 안 됐나, 한 줄>
   - 고친 것: <무엇을 바꿨나> (`파일:라인`)
   - 영향: <엮인 곳과 확인 결과>
   - 남은 위험: <없음 | 무엇>
   ```
3. 테스트를 실행하고 보고서를 남긴다. 관련 테스트 찾기·실행·지난번과 비교는 스크립트가 한다:
   ```bash
   SCRIPT=bin/test-report.sh
   [ -f "$SCRIPT" ] || SCRIPT="$HOME/.monggle/bin/test-report.sh"
   bash "$SCRIPT" --kind fix --note <메모 파일>   # 테스트 명령을 직접 주려면: -- <명령>
   ```
4. 결론이 "검증되지 않았습니다"(관련 테스트 없음)면 이번 버그를 잡는 가장 작은 테스트 하나를 추가하고 다시 돌린다.

## 5. 보고
스크립트가 출력한 결론 한 줄(✅/⚠️/❌)과 다음 할 일을 그대로 전하고, **"보고서를 열어볼까요?"** 라고 묻는다.
보겠다고 하면 `bash "$SCRIPT" --open-last --kind fix` 로 연다. 묻지 않고 열지 않는다.
